一、失败原因
------------
xcodebuild 在 Release-iphoneos 配置下构建 SbxlmKeyboard.appex 时链接失败:

  ld: symbol(s) not found for architecture arm64
  clang: error: linker command failed with exit code 1
  ** BUILD FAILED **
  失败命令: Ld .../SbxlmKeyboard.appex/SbxlmKeyboard normal (in target 'SbxlmKeyboard' from project 'Hamster')

具体症状是数百个 librime C 接口符号未定义:
  "_RimeSetup"、"_RimeInitialize"、"_RimeProcessKey"、"_RimeConfigOpen"、
  "_RimeGetCommit"、"_rime_get_api" 等 (全部引用自 RimeKitObjC.o)。

根因: Hamster.xcodeproj 中 SbxlmKeyboard target 的 Frameworks 链接阶段
(C03EC3B72B066C1100DB741E) 缺少 librime.xcframework。
SbxlmKeyboard 通过 SwiftPM 链接 HamsterKeyboardKit(其传递依赖包含
RimeKit/RimeKitObjC, 引用全部 Rime* C 符号), 但工程里只链接了 boost_*、
libglog、libleveldb、libmarisa、libyaml-cpp、libopencc 等 xcframework,
唯独漏掉了 librime.xcframework, 导致链接器找不到 Rime* 符号。

对照同工程的 HamsterKeyboard target, 其 Frameworks 阶段包含
librime.xcframework(位于 boost_atomic 与 boost_regex 之间), 因而
HamsterKeyboard 链接正常, 只有 SbxlmKeyboard 失败。

补充背景: 前几次运行(34366506587 等)分别因 boost_locale.xcframework
不存在、iOS 最低版本(15.0 vs 16.0)不匹配而失败, 已被提交 d1b047c 修复;
本次是修复上述问题后暴露出的下一个链接问题。

三、第二轮修复(提交 1e7bc3b / 8ebc2eb): RimeReplaceInput 私有符号
------------------------------------------------------------------
推送 885f288 后重新构建(运行 #5 34369289306)仍失败, 但错误收敛为唯一
未定义符号:

  Undefined symbols for architecture arm64:
    "_RimeReplaceInput", referenced from:
      -[IRimeAPI replaceInputKeys:withStartPos:AndCount:AndSession:]
        in RimeKitObjC.o

根因: RimeReplaceInput 是已停用的 imfuxiao/LibrimeKit(iOS 预编译
librime)私有的扩展 C 接口, 官方 rime/librime 从 1.5.3 至今从未实现过该
符号(已逐一核对各版本 rime_api.h, 并在 GitHub 全站确认无任何实现)。
本仓库 6bfc902 起改用仍在维护的 amorphobia/LibrimeKit v0.1.0 发布物
(官方 librime 源码构建, 不含私有扩展), 导致链接期找不到
_RimeReplaceInput。该问题影响所有链接 RimeKit 的目标(主 App、
HamsterKeyboard、SbxlmKeyboard), 只是 SbxlmKeyboard 先编译完成而最先报错。

修复: 不再调用不存在的私有符号。在
Packages/RimeKit/Sources/ObjC/irime_api.m 的
replaceInputKeys:withStartPos:AndCount:AndSession: 中改用 librime 公开
API 实现等价行为(注: 本项目 vendored 的 rime_api.h 同时暴露传统
Rime* 全局函数与 rime_get_api() 函数指针结构体, 输入读取/按键处理
只能通过后者调用):
  - 通过 rime_get_api()->get_input 读取当前编码输入, 按 (startPos,
    count) 重组编码为前缀 + 新文本 + 后缀;
  - 用 rime_get_api()->process_key 逐字退格(XK_BackSpace = 0xFF08)
    清空原编码;
  - 再逐字键入新编码, 由引擎按新编码重新生成候选。
并加入边界保护: 非 ASCII 编码/新文本时直接返回 NO, 不做破坏性改动。

说明: 上游同源项目(如 xingbofeng/VoxFlow)对同一问题采用返回
False 的兼容空桩, 会直接禁用"九宫格拼音修改编码"功能; 本修复采用
公开 API 等价实现, 尽量保留原功能行为。若日后更换回带该私有扩展的
librime 预编译包, 此段逻辑仍可正常使用。

另注: 第一版修复(1e7bc3b)误用了不存在的全局函数 RimeGetInput/
RimeProcessKey, 运行 #6 编译失败; 8ebc2eb 改为 rime_get_api() 函数表
后通过。

四、第三轮修复(提交 895e2a4): 构建工具链迁移到 Xcode 26
--------------------------------------------------------
运行 #7 (34371364231) 通过全部 Rime 相关编译与链接后, 失败点转移到
HamsterKeyboard target 编译 Swift 文件导入 KeyboardKit 模块:

  error: failed to build module 'KeyboardKit'; this SDK is not supported
  by the compiler (the SDK is built with 'Apple Swift version 6.3.3
  effective-5.10', while this compiler is 'Apple Swift version 6.1.2
  effective-5.10'). Please select a toolchain which matches the SDK.
  以及: no such module 'FoundationModels'

根因: 本项目通过 SwiftPM 依赖的 KeyboardKit 10.9.4
(KeyboardKit/KeyboardKit.git) 在 Package.swift 中声明为预编译二进制
(binaryTarget: KeyboardKit-Binaries 10.9.4), 该二进制由 Xcode 26 系列
工具链(Swift 6.3.3 + iOS 26 SDK)构建, swiftinterface 引用了 iOS 26 SDK
才存在的 FoundationModels 模块。而 CI 此前使用 macos-15-intel runner +
Xcode 16.4(Swift 6.1.2 / iOS 18.5 SDK), 编译器版本低于构建 SDK 版本,
且缺少 FoundationModels 模块, 无法编译该模块。

修复: 将 CI 迁移到带 Xcode 26 系列工具链的 runner:
  - .github/workflows/keyboardkit-macos-build.yml:
      runs-on: macos-15-intel -> macos-26
      xcode-version: '16.4' -> '26.6'
  - .github/workflows/ci.yml: 同样更新(供手动归档构建使用)

六、第五轮修复(提交 064bc17): StandardKeyboardActionHandler 初始化器
-------------------------------------------------------------------
运行 #9 (34373348228) 失败:
  全部代码编译通过后, HamsterKeyboard.appex 链接失败:
    Undefined symbols: KeyboardKit.StandardKeyboardActionHandler
    .init(controller:) ...

根因: KeyboardKit 10.9.4 预编译二进制并未导出 convenience
init(controller:), 只存在带 10 个参数的 designated initializer
(已解包 KeyboardKit.xcframework 的 swiftinterface 逐一核对, 并对照
其他 KeyboardKit 10.9 实际项目验证调用方式)。

修复(commit 064bc17): HamsterKeyboard/KeyboardKit10ActionHandler.swift
改用 designated 初始化器, 参数取自 controller.state / controller.services:
  keyboardContext、keyboardBehavior、autocompleteContext、
  autocompleteService、emojiContext、feedbackContext、feedbackService、
  keyboardAppContext、spacebarDragGestureHandler。

七、第六轮修复(提交 afe0d71): App Shortcut 短语占位符
-----------------------------------------------------
运行 #10 (34374207899) 失败:
  两个键盘扩展均链接成功后, 主 App target 的 AppIntents 元数据导出失败:

  "RIME Sync using ${applicationName}"、"使用${applicationName}同步RIME"
  "RIME Deploy using ${applicationName}"、"使用${applicationName}重新部署RIME"
